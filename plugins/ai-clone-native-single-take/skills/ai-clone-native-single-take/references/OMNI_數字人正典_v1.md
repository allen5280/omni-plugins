## A. 底圖 DNA（★最被低估的一層）

### A-1 根因：桌面的細碎高光＝爆白光斑的原料

柏維哥 2026-07-29 回報：「手接觸到鍵盤的時候偶爾會發生一圈發光輪廓，桌面上會有亮點爆白光，
而且手放在鍵盤上時有時候會被鍵盤吃掉。」

**根因不在模型，在底圖。** 原底圖的桌面是整片混音台旋鈕，佈滿數百個細碎鏡面高光點。
Avatar IV 動畫化時會把這些高光**在時間軸上暈開**，形成：
- 手緣一圈發光輪廓（高光沿著手的邊界溢出）
- 桌面爆白光團（多個高光點被合併放大）
- 手被吃掉（手與旋鈕在明度上互相吞噬，邊界消失）

實測：v30 全片 f426–433（17.04–17.32s）過曝像素從中位數 284 暴衝到 **14486**。

### A-2 底圖鐵律

```
① 手要放的那塊桌面 ＝ 乾淨、平滑、深色、柔和反射
   零鍵盤、零旋鈕、零按鈕、零細碎高光點
② 發亮的道具可以有，但要放在「遠離手」的位置（畫面角落／後景）
③ 所有道具只能柔光漫射，不要硬鏡面高光、不要 bloom、不要 lens flare
④ 人物、臉、雙手、戒指、手錶、念珠、麥克風 → 一個像素都不能被 AI 重畫
```

### A-3 改底圖的正解 SOP

```
① Higgsfield nano_banana_pro（＝nano_banana_2）2K，把現有底圖當 reference
   prompt 要寫成「只改 X，其餘一個像素不動」的硬約束
   ★實測身分保真 0.112（幾乎零損失）
② ★戒指／小物件的「移動」不要交給 AI —— 模型只會「加」不會「移」，會變兩個。
   第二輪 AI 修一定會改到手勢。
   正解＝本機外科式修補：沿目標畫粗帶當遮罩 ∩ 排除深色背景 → cv2.inpaint(TELEA, r=9)
   （v2 實測只動 2045 px ＝ 全圖 0.048%，手勢與臉零改動）
③ 生完必驗：五官偏差 ≤5%、身分保真 ≤0.45、★手部區域像素 diff（AI 有沒有偷改手）
④ 縮回原尺寸（940×1672），維持已驗證的輸出構圖
```

## B. 文案 DNA（L1 閘）

### B-1 為什麼文案決定聲音品質

**文字之於 TTS ＝ 音檔之於動畫模型。**
神經 TTS 的 G2P（破音字消歧）與韻律預測（斷句／重音／語調）**100% 由文本決定**，
`voice_id` 只接在聲學模型那層，`speed/pitch/vol` 只是全域縮放 —— 插不上手。

### B-2 v16 真人基準的指紋

| 文本 | 漢字 | 分句 | 句長標準差 σ | 成語 | 問句 |
|---|---|---|---|---|---|
| ★v16（真人講完轉逐字稿）| 67 | 6 | **1.57** | 0 | 0 |
| 寫出來的壞文案 | 44–56 | 4–7 | 2.28–**7.58** | 0–3 | 0–1 |

**σ 越低 ＝ 節奏越均勻 ＝ 越像真人呼吸。** σ 7.58（句長 3 到 20 字亂跳）＝ TTS 每句都要重設語調曲線。

### B-3 L1 閘規則

```
每逗號分句 8–14 漢字
句長標準差 σ ≤ 2.2
成語／四字書面語 ＝ 0     ← 觸發朗讀腔，提速時直接崩字（土法煉鋼→圖法鏈剛）
問號 ＝ 0                 ← 改寫成內心話陳述（「我就在想，到底還有誰可以談」）
★ 目標秒數 → 漢字數 ＝ round(6.42 × 目標秒數)
   （Avatar IV 沒有整數秒限制，音檔多長片就多長，舊的 −0.2 死空氣修正已作廢）
破音字掃描 → 自動產生最小字典
```

**MUST_FIX 字典（只有這 9 個字，多一個都不要加）**
`誰 著 塞 血 薄 率 差 曾 藏`
> ★「誰」必放 `誰/(shei2)`。陸製模型預設書面音 shuí，聽起來就是「水」。

**為什麼字典不能多加**：每條字典＝關掉該詞的韻律預測 → 輕聲消失、變調消失、詞邊界插微停頓。
18 條字典實測讓語音慢 8.6%，就是「節奏怪怪的」元兇。**字典是手術刀不是漆刷。**

## C. 聲音 DNA（L2）

```
endpoint   https://api.minimax.io/v1/t2a_v2        ← Bearer sk-api-…（新版金鑰不需要 GroupId）
model      speech-2.6-hd                            ← 柏維哥 A/B 親耳選的 2 號
voice_id   AllenDJIClone01
pitch 0 ｜ vol 1.0 ｜ sample_rate 32000 ｜ mp3
speed      ❌ 絕不寫死
           自動校準：跑一次 speed=1.0 → 量實際字秒率 → speed = 6.42 ÷ 實測 → 重跑
           實測收斂 1.16–1.26（2026-07-29 24 字實測 5.17 cps → speed 1.242）
TARGET_CPS 6.42 字/秒（真人 6.37 ／ 柏維哥認可版 6.46）
best-of-3  三個 take 全驗，選字秒率最接近 6.42 的
```

**L3 驗收**：whisper 逐字稿 vs 原文相似度 ≥ 0.96（同音字白名單過濾）。不過就報警，不硬送。

**跨文本比較只有這 5 個指標有效**：F0 中位／F0 起伏／停頓數／字秒率／ASR 準確率。
❌ 頻譜 RMS 距離、MFCC-DTW 總分 **不能跨文本排名**（同時測音色＋內容）。

**備用手術刀**：`<#0.6#>` 停頓標記 speech-2.6-hd 吃（實測 3.579s→4.859s），
某句氣口對不上時直接打標記，不用改字。

```

          ★ 寫 audio/wav 會被退 400543

生成      POST https://api.heygen.com/v3/videos
          ★ 不要用 /v2/video/av4/generate，那個永遠輸出 720×720
查狀態    GET  https://api.heygen.com/v1/video_status.get?video_id=…
額度      GET  https://api.heygen.com/v3/users/me    → wallet.remaining_balance（美元）
```

### D-2 正典 payload

```json
{"type":"image",
 "image":{"type":"asset_id","asset_id":"<底圖>"},
 "audio_asset_id":"<音檔>",
 "aspect_ratio":"9:16",
 "resolution":"1080p",
 "expressiveness":"high",
 "motion_prompt":"<Z2_DESK>"}
```

| 欄位 | 為什麼 |
|---|---|
| `aspect_ratio` + `resolution` | ★兩者都填才會出 1080×1920，少一個就掉回 720×720 |
| `expressiveness:"high"` | ★唯一能讓桌上那隻手動起來的開關。實測桌手動能 1.288 → 2.924（2.3 倍）|
| `motion_prompt` | 見下 |

### D-3 Z2_DESK 正典 prompt

```
The hand wearing the black watch, resting on the desk, keeps moving: it lifts a few centimetres
off the desk, the fingers spread open, then it settles back down onto the desk - over and over,
slowly and gently, all the way through. His facial features stay exactly as they are in the reference
photo. The camera is locked off and completely static.
```

**這個 prompt 為什麼長這樣（每個設計都是踩過坑換來的）**

| 設計 | 原因 |
|---|---|
| 用「戴黑色手錶、放在桌上的那隻手」而不是 left/right | ★模型用**主角自己的左右**，跟「畫面左下那隻手」相反 → 指令自相矛盾 → 長出第三隻手。改錨定後多手 11.5% → 0% |
| 只鎖「facial features」，不鎖頭／頸／肩 | 約束詞會把手一起鎖死（動能掉到 1.0，比底片還低）。加「head and shoulders stay steady」實測多手暴增到 46 幀 |
| 極短，不加額外約束詞 | 字越少動作越大。加約束詞會把動作壓死 |
| 不寫光線描述 | ★Avatar IV 是 audio-driven，光已烘焙在底圖裡。加光線描述不是沒作用就是動搖 identity lock。**光線描述是 B-roll 生成模型（Seedance/Kling）的工具，不是這裡的** |
| 不寫鏡頭運動 | 同上；而且我們要的就是鎖死靜止 |

**成本**：US$3.00／分鐘（720p/1080p）、US$4.00／分鐘（4K）。按實際秒數計費。
52.56 秒 ＝ **US$2.63**。錢包制（`billing_type: wallet`），在
`app.heygen.com/developers/billing` 儲值。

## F. 修補 DNA（L5）

```
連續 ≥0.5 秒的壞段  → B-roll 蓋掉（交給下游剪輯層）
單幀／數幀的壞點    → ★幀級修補（不打斷 a-roll 的信任累積）
```

`repair.py` 的方法：**時間中位數背景還原 + 膚色保護 + 連續 alpha 羽化**
- 背景 ＝ 壞段前後各 10 幀的 per-pixel median（桌面是靜態的，所以乾淨）
- alpha ＝ 依「比背景亮多少」連續漸變（二值遮罩吃不掉外圈柔光暈）
- 膚色 dilate 25px 保護 → 手一個像素不碰
- 背景本身就亮的地方（median > 145）不碰 → 不會誤刪原有內容

**實測（v30 → v30R）**：過曝峰值 14486 → 610，超標幀 8 → 0，手與臉零改動。

⚠️ **不要用 FULL 模式（ROI 內整片還原）** —— 膚色保護的邊界會在手周圍留一圈發光輪廓，反而更假。

## G. 為什麼不用研討會講的那幾招（有依據的反駁）

台灣數字人專家（大偉哥）研討會的 A1–A6，**不是每一條都適用**：

| 他的建議 | 適不適用 | 為什麼 |
|---|---|---|
| A1 b-roll 蓋掉出錯片段 | ✅ 適用，但只適用「連續 ≥0.5 秒」 | 單幀用幀級修補更好，不打斷人臉信任累積 |
| A2 prompt 加光線細節 | ❌ **不適用於 Avatar IV** | 他的場景是 Seedance／可靈這種**會生成整個畫面**的模型，光線描述真的會改變渲染。Avatar IV 是 audio-driven avatar animation，光已烘焙在參考照片裡 → 加了無處著力，還可能動搖 identity lock。**這招要用在 B-roll 生成上** |
| A3 解剖級 prompt + 鏡頭語言 | ❌ 同上，且 ⚠️ 危險 | Avatar IV 的 prompt 是脆弱平衡：加「head and shoulders steady」多手暴增到 46 幀；加約束詞會把手鎖死。**這招也是 B-roll 的工具** |
| A4 教 AI 幫你寫 prompt | ✅ 適用於 B-roll | a-roll 的 prompt 已經是正典，不需要再生成 |
| A5 動作遷移 motion control | ❌ **不能用在主口播** | 動作遷移會讓臉部跟著 driving video 走 → **破壞對嘴**。我們的嘴型必須鎖死在 MiniMax 那支音檔上。而且 Kling 單次上限 15 秒，52 秒要接力＝臉會二代漂移（已是死路）|
| A6 抽卡 → 剪輯組合 | ⚠️ 降級方案 | Avatar IV 一次就能生完整 52 秒且近乎決定性，不需要抽卡。抽卡是 Seedance 那種短片模型的限制下的產物 |
| 「AI 味＝畫面節奏太單調」 | ✅ 正確，但屬於剪輯層 | 這是 B-roll／字幕／節奏的事，不是 a-roll 母帶的事 |

**一句話**：他的 know-how 有一半是「怎麼讓生成模型演得像」，我們這條線是「讓真人的臉開口說話」，
不同的問題。**把他的招用在對的層，用錯層會把已經驗收通過的東西弄壞。**
